# Enterprise Knowledge Assistant — Interview POC

A small, locally demoable Spring Boot + Spring AI implementation of the Knowledge Assistant assignment.

## Architecture

Browser -> REST Controller -> Access/Date filtering -> Embedding-based semantic retrieval -> Evidence validation -> ChatClient -> Answer + source references

The important security boundary is that unauthorized documents are filtered BEFORE their text is passed to the LLM. Document text is treated as untrusted data, so instruction-like content cannot change application rules.

## Why this is deliberately simple

The assignment is time-boxed. This POC uses an in-memory synthetic corpus and embeddings generated by Ollama. It avoids authentication, OCR, distributed search, and production deployment, which the assignment explicitly places out of scope.

For production, replace the in-memory repository with PostgreSQL/PGVector or another vector store, use enterprise identity/authorization, persist document versions, add observability, rate limits, prompt-injection evaluation, encryption, and HA model/vector services.

## Run locally

Requirements: Java 21, Maven, Ollama.

```bash
ollama pull llama3.2
ollama pull nomic-embed-text
mvn clean test
mvn spring-boot:run
```

Open http://localhost:8080

## API

```bash
curl -X POST http://localhost:8080/api/ask \
 -H 'Content-Type: application/json' \
 -d '{"question":"How long are transaction records retained?","userAccess":["EMPLOYEE"],"effectiveDate":"2026-06-01"}'
```

## Demo scenarios

1. Direct: `What is the transaction retention period?` / EMPLOYEE / 2026-06-01 -> 7 years, source POL-RET-2026.
2. Different wording: `How long do we keep transaction history?` -> semantic retrieval.
3. Combined: `What happens when a payment is stuck and how does the architecture process it?` -> operations + architecture sources.
4. Changed information: use date 2025-06-01 -> 5 years; use 2026-06-01 -> 7 years.
5. Restricted: ask for high-value refund approval as EMPLOYEE -> FINANCE document is never eligible or cited.
6. Conflict: ask operational event retention as AUDIT -> conflict between OPS-RET-A and OPS-RET-B.
7. Unknown: ask an unrelated question -> insufficient answer.
8. Prompt injection: ask about vendor note -> instruction-like text remains document content.

## Production readiness discussion

This is a runnable POC, not production-ready. The architecture is production-oriented, but the storage, authentication, observability, resilience, evaluation, and deployment layers are intentionally simplified.

## Interview explanation

- ChatClient is the generation boundary.
- EmbeddingModel converts question and documents into vectors.
- Retrieval is scoped by access group and effective date before generation.
- The LLM receives only selected evidence and a strict system policy.
- The API returns status plus source references so an application can verify claims.
- Conflicts are handled deterministically instead of asking the LLM to guess.
